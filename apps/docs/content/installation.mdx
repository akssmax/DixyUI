## Install

<InstallCommand packages={["@dixy-ui/react@beta", "@dixy-ui/themes@beta"]} />

`@dixy-ui/themes` is optional: it adds the starter themes. `react` and `react-dom` 19 are peer dependencies. `motion` 14 is optional and only needed for `@dixy-ui/react/motion`.

Any package manager works; Dixy has no install scripts. pnpm is our default: from version 10 it blocks dependency install scripts unless you allow them, and stops packages from importing dependencies they didn't declare.

## Add the stylesheet once

Import the stylesheet at the application root. Dixy ships CSS variables and component styles; consumers do not need a Tailwind compiler. CSS layers allow application styles to override library defaults.

For TanStack Start, the root route imports the stylesheet before rendering the page. Verify the production HTML includes styles before hydration.

### With Tailwind CSS v4

Tailwind's reset (`border: 0 solid` on every element) lives in its `base` layer. Layers declared first lose, so if Dixy's stylesheet loads before Tailwind, the reset strips borders and backgrounds from Dixy's controls. Declare the layer order yourself, then import Dixy from the same CSS file:

<CodeBlock
  language="css"
  filename="app.css"
  code={
    '@layer theme, base, dixy, components, utilities;\n@import "tailwindcss";\n@import "@dixy-ui/react/styles.css";\n@import "@dixy-ui/themes/retro-os.css";'
  }
/>

Dixy now sits above Tailwind's reset and below its utilities, so a utility class still overrides a component default. Don't also import Dixy's CSS from JavaScript: a JS import that loads first declares the `dixy` layer before this order exists.

## Load the theme's fonts

Themes name their fonts but don't bundle them. Install the matching [Fontsource](https://fontsource.org) packages and import them once at the app root. Without them, headings fall back to a generic font. These are the fonts for the theme you're wearing; switch themes in the header to see another's.

## Make room for overlays

Your application layout root should use `isolation: isolate`. Keep `body` positioned relatively so dialog backdrops can cover the scrolled viewport on iOS Safari. Avoid transforms on an overlay’s containing block.

<CodeBlock
  language="css"
  filename="app.css"
  code={"body { position: relative; }\n.app-root { isolation: isolate; }"}
/>

## Supported environments

- **React** 19, with client or server rendering.
- **Browsers:** Chrome/Edge 117+, Safari 16.2+, Firefox 121+. Dixy's styles use `oklch()`, `color-mix()`, `:has()`, container queries and subgrid. Some decorative glass blurs need Safari 18+ and fall back to a solid surface before that.
- **Accessibility:** WCAG 2.2 AA is the target. Base UI and React Aria provide the behaviour, and automated axe checks run in the test suite. Manual screen-reader, high-contrast and zoom testing is still in progress.
