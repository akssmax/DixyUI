# Base UI component refresh — 2026-10-15

The approved existing-component pass extends the Checkbox, Switch and Tabs approach across the remaining Base UI families. This is an implementation pass; the comprehensive browser, assistive-technology and WCAG 2.2 AA release review remains deferred at the user's request. New families such as ButtonGroup and AvatarGroup remain in [the component roadmap](COMPONENT_ROADMAP.md).

## Public contracts and composition

Dixy keeps Base UI's actual compound parts, including Root, Trigger, Portal, Positioner, Popup, List, Item and Indicator where those parts exist. Root value types, event details/cancellation, refs, render/className/style callbacks, form behavior, focus and presence remain with the primitive. Simple components such as TextField, Toggle, Separator and Form stay single components rather than gaining artificial compound wrappers.

Visual settings belong on a DOM-owning part. In particular, Select/Combobox/Autocomplete Roots retain their generic contracts without a styling context wrapper. Configure their Trigger/Input/InputGroup and portaled Popup independently. RadioGroup, ToggleGroup and Slider preserve generic value inference. Material and radius inherit Theme when omitted; a component's explicit value overrides the theme. Circular radios retain circular geometry, and large surface radii are capped so panel content remains usable.

The generated API includes each local public visual interface. Each Base UI page has an authored composition tree. Thirty-three refreshed pages have aligned primary controls and complete source; useful size, treatment, color, radius, material or layout comparisons follow the playground. Their 121 categories use the same shared card as Checkbox and Switch: one preview with labeled, independently interactive examples and one expandable/copyable complete source block below. Rows wrap within the available space; compact controls and larger compositions have different widths. Comparison categories mount as they approach the viewport, avoiding simultaneous offscreen live demos. Each copy includes all sibling instances, their helper functions and the matching Theme configuration, and is checked against the compiled package.

## Documentation uses Dixy

The shared Preview/Code control now uses Tabs.Root, List, Tab, Indicator and Panel rather than hand-maintained ARIA and keyboard handlers. Boolean settings use Switch.Root/Thumb. Property/theme dropdowns use Select's actual compound parts through a small docs-only option adapter. Buttons, retry/copy/reset actions, text inputs and range controls use public Button/IconButton, TextField and Slider. Navigation groups, theme settings, source disclosures and primitive API disclosures use Collapsible. The docs still consume compiled public package exports.

Ordinary headings, paragraphs, navigation links and data tables retain semantic HTML. Existing option declarations are data for the docs Select adapter and are not native dropdowns in the rendered UI. The preset JSON editor remains a native textarea while public Textarea remains planned. Search retains its existing result-navigation logic with the styled input; a dedicated search-composition review is part of subsequent interaction validation.

## Reference decisions

The references guide anatomy and useful examples, not replacement dependencies or a claim of identical behavior. No second UI stack, icon pack, animation runtime, texture request or blur effect was added. Static finishes remain an optional CSS export. Feedback and presence use the generated Dixy recipes, while Base UI retains mount/unmount ownership; reduced motion is immediate. Slider, scroll and drawer direct manipulation keep their functional positions.

## Validation boundary

Required workspace checks, packed consumer checks and focused implementation smoke review are recorded in BUILD_LOG.md. Three new contract tests protect visual prop forwarding/render/ref behavior, typed object selection cancellation/default artwork, and scalar/range inference. Existing behavioral tests continue to run. Generated examples are checked against the compiled public library.

Pending release work includes the full visual/state matrix, text and non-text contrast across palettes and material composites, actual screen-reader/browser combinations, forced colors, native OS preferences, 200–400% zoom, physical touch and Safari/Firefox. Existing Checkbox/Switch/Tabs measurements remain scoped to their prior evidence and do not establish conformance for these refreshed families. Personal learning items remain unchecked.
